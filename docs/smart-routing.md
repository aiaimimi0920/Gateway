# 会话黏性与分档路由（首版）

会话黏性记录最近实际发送的服务商，不以调用成功为前提。只使用客户端真实
session 标识，作用域包含租户、项目和 API Key；没有 session 不生成伪 ID，
不退化为用户级或平台级成功亲和。切换模型后，不沿用旧模型的会话记录。
记录在发送预算准入后、开始发送前同步更新；晚完成的旧请求不会覆盖新记录。

候选必须先满足权限、协议、模型、凭证、冷却与额度要求。合规的黏性候选优先，
其余候选按策略排序。普通传输重试沿用现有重试预算；明确的模型或认证拒绝无需
重复发送。已输出后不自动重放，错误流不能伪装为成功完成。

## 三层策略

覆盖顺序是请求 > API Key > 全局。每层必须是三个维度的完整排列，重复或未知
维度报错。请求不能通过排序扩大自身授权范围。

全局设置位于现有 `gateway.json`，与 `enable_management_ui` 并存，重启后读取：

```json
{
  "routing_policy": {
    "order": ["availability", "intelligence", "price"]
  }
}
```

API Key 管理接口现有 `metadata` 增加可选字段（更新时保留其他 metadata）：

```json
{"routingOrder": ["price", "availability", "intelligence"]}
```

单次请求使用专用头，而非上游业务参数：

```http
x-gateway-routing-order: availability,intelligence,price
```

此头在出站头构造中剥离。未指定维度顺序时，默认可用性 > 智力 > 价格。
本轮提供配置/API 合同，不包含新的可视化策略编辑器。

## 分数与价格

- 可用性以服务商账户 × 请求模型为单位；初始 100，失败扣 15，完整成功加 5。
- 每分钟恢复 1 分，上限 100；读取时计算，不建立后台计时任务。
- 本地预算终止、取消以及请求参数/上下文/内容拒绝不扣可用性分。
- 可用性是当前进程的有界运行数据，重启后重新从 100 开始，不修改凭证数据库。
- 四档边界为 `[75,100]`、`[50,75)`、`[25,50)`、`[0,25)`。
- 智力默认全部 100；自动评测关闭，不产生评测调用。可选的人工测量值和有效期
  作为将来入口，不宣称已经验证某模型是否量化。
- 价格复用现有模型报价和账户/组倍率，以相同输入输出各一百万 Token 的费用比较。
  这是统一参考负载，不是本次请求的精确账单；缺失报价排在已知报价之后，不当免费。
- 同档才比较下一个维度，不以 84 对 80 的小分差压过后续智力或价格。

可选 `routing_policy.measurements` 可配置 `provider`、`model`、`intelligence`、
`valid_until_unix`、`input_per_million`、`output_per_million`。智力分数过期回到
首版默认 100；手工价格表示已包含账户和组倍率的最终有效价，须与现有报价使用
同一币种，不会再乘倍率。不存在自动评测调度器。

## 流错误修复边界

OpenAI 兼容流在交给客户端前检查有界 SSE 前缀。跳过明确无输出的生命周期事件，
遇到第一条有效/未知业务事件即停止预读并原样回放，最多保留 64 KiB。
明确的模型不存在错误可让带工具声明的请求安全切换候选；普通网络错误仍受既有
重放限制。Responses 的后续失败保留原始错误事件，并仍以失败完成审计，不能
合成 `response.completed` 或 `[DONE]`。
