# 会话黏性与分档路由（首版）

会话黏性记录最近实际发送的服务商，不以调用成功为前提。只使用客户端真实
session 标识，作用域包含租户、项目和 API Key；没有 session 不生成伪 ID，
不退化为用户级或平台级成功亲和。切换模型后，不沿用旧模型的会话记录。
记录在发送预算准入后、开始发送前同步更新；晚完成的旧请求不会覆盖新记录。
单次上游调用重试结束仍失败，或已交付的流确认上游失败时，解除该请求留下的
黏性，让下一次请求重新按智能分档排序。中间重试不解除；客户端取消、本地预算
终止及参数拒绝不解除。解除操作核对请求 ID，不能清除并发较新请求的黏性。

候选必须先满足权限、协议、模型、凭证、冷却与额度要求。合规的黏性候选优先，
其余候选按策略排序。普通传输重试沿用现有重试预算；明确的模型或认证拒绝无需
重复发送。已输出后不自动重放，错误流不能伪装为成功完成。

HTTP 403 的已识别 HTML 诊断页（`upstream_html_diagnostic`）属于上游调用失败：
该服务商账户 × 请求模型扣 15 分，解除本次失败黏性，不重试同一失败凭据，
而按本请求已完成智能排序的候选队列继续选择。带工具的 Chat/Responses 请求也可
在交付前切换，但只逐次增加下一次发送资格，总计不超过 6 次、截止时间不重置。
候选仍须通过授权、模型/协议、凭据、冷却和额度检查。未知 HTML、明确权限/内容
拒绝不因此放行，媒体创建及已交付响应不重放；没有合规候选时仍返回失败。

## 三层策略

覆盖顺序是请求 > API Key > 全局。每层必须是三个维度的完整排列，重复或未知
维度报错。请求不能通过排序扩大自身授权范围。

全局设置位于现有 `gateway.json`，与 `enable_management_ui` 并存，重启后读取：

```json
{
  "routing_policy": {
    "order": ["availability", "intelligence", "price"]
  }
}
```

API Key 管理接口现有 `metadata` 增加可选字段（更新时保留其他 metadata）：

```json
{"routingOrder": ["price", "availability", "intelligence"]}
```

单次请求使用专用头，而非上游业务参数：

```http
x-gateway-routing-order: availability,intelligence,price
```

此头在出站头构造中剥离。未指定维度顺序时，默认可用性 > 智力 > 价格。
本轮提供配置/API 合同，不包含新的可视化策略编辑器。

## 分数与价格

- 可用性以服务商账户 × 请求模型为单位；初始 100，失败扣 15，完整成功加 5。
- 每分钟恢复 1 分，上限 100；读取时计算，不建立后台计时任务。
- 本地预算终止、取消以及请求参数/上下文/内容拒绝不扣可用性分。
- 可用性是当前进程的有界运行数据，重启后重新从 100 开始，不修改凭证数据库。
- 四档边界为 `[75,100]`、`[50,75)`、`[25,50)`、`[0,25)`。
- 智力默认全部 100；自动评测关闭，不产生评测调用。可选的人工测量值和有效期
  作为将来入口，不宣称已经验证某模型是否量化。
- 价格复用现有模型报价和账户/组倍率，以相同输入输出各一百万 Token 的费用比较。
  这是统一参考负载，不是本次请求的精确账单；缺失报价排在已知报价之后，不当免费。
- 同档才比较下一个维度，不以 84 对 80 的小分差压过后续智力或价格。
- 控制台累计调用数不是当前可用性分数，也不意味着这些调用都使用当前路由版本。
  排查时应按审计 `selectionStrategy` 和时间区间区分旧 `priority_weighted` 与新策略；
  低分是降低排序，不是永久禁用，授权候选耗尽后的回退仍可能调用低分服务商。

可选 `routing_policy.measurements` 可配置 `provider`、`model`、`intelligence`、
`valid_until_unix`、`input_per_million`、`output_per_million`。智力分数过期回到
首版默认 100；手工价格表示已包含账户和组倍率的最终有效价，须与现有报价使用
同一币种，不会再乘倍率。不存在自动评测调度器。

## 流错误修复边界

OpenAI 兼容流在交给客户端前检查有界 SSE 前缀。跳过明确无输出的生命周期事件，
遇到第一条有效/未知业务事件即停止预读并原样回放，最多保留 64 KiB。
明确的模型不存在错误可让带工具声明的请求安全切换候选；普通网络错误仍受既有
重放限制。Responses 的后续失败保留原始错误事件，并仍以失败完成审计，不能
合成 `response.completed` 或 `[DONE]`。

## 模型临时硬熔断

硬熔断与上述软性分数分离。作用域为服务商、实际凭证所属本地组和实际上游模型；
模型别名映射到同一个上游模型时，共用这一故障记录。分组外的数据库/Redis 凭证
按凭证身份隔离；同一凭证同时加入多个本地组时采用保守联合限制。

- 60 秒内连续 3 次合格上游故障后禁用，冷却依次为 2、8、32、60 分钟，之后封顶。
  上游限流可立即进入冷却，且尊重比本地冷却更长的 `Retry-After`。
- 超时、网络/服务故障和已识别 HTML 诊断页 403 计入；取消、本地预算、参数、上下文、
  内容拒绝不计入。普通鉴权 401/403 仍由已有凭据/权限限制处理，不混成模型故障。
- 到期后只准一个实际请求试放，失败立即升档；两次完整成功至少间隔 30 秒才关闭熔断。
  中性取消会释放试放资格但等待 30 秒再试，不把取消算成功。稳定成功 30 分钟后清级别。
- 硬限制在凭据池、模型映射和路由排序之前排除目标，并在实际发送前再次校验。
  黏性和排序不能绕过；无可用候选时不能捞回被禁用目标。共享健康检测不会解除调用熔断。
- 流式成功以真实流终态为准，不以 HTTP 200 响应头为准；旧在途回包不能清除新的熔断。
  人工启停标志、监控限制和熔断分别拥有自己的状态，不互相写入或解除。

当前实现为单运行实例内的有界状态，重启不保留、多个进程不共享。管理站点健康响应
增加 `model_circuits` 诊断字段；分组监控编辑器和 PostgreSQL 公开模型目录的一致性接入
仍在后续开发范围，不能仅凭此章节当作站点健康全部功能交付。

## 余额拒绝与手动禁用后的回退（2026-10-24）

明确的上游 HTTP 402/403 余额拒绝，包括带“用户剩余额度”和“需要预扣费额度”的
“预扣费额度失败”，直接把具体凭证置为第三级冷却（32 分钟）；到期试放仍失败进入
第四级（60 分钟）。余额冷却跨该凭证的模型生效，但不封禁同服务商、同授权组内的
其他凭证。没有显式凭证池时使用该服务商的默认凭证身份。普通模型故障仍沿原分组/
模型熔断处理，不能反向污染余额冷却；本地访问密钥余额或授权错误不进入上游熔断。

实际路由为每个服务商保留最多 6 个不同的合规凭证候选，首选只推进一次 RR；备用
凭证不增加服务商在首次加权选择中的权重。既有请求总发送预算不增加。明确的预扣费
拒绝允许同请求切换，输出前 SSE 的同类错误也适用；已移交或已输出的流不重放。

手动禁用是硬限制，不被会话黏性、自动试放或智能排序解除。对绑定账号分组的访问
密钥，可在其具体授权成员内切换服务商，不能跨到组外凭证，也不能越过 key 的
provider/model 白名单。授权成员全部停用或暂不可用时返回
`503 / authorized_candidates_unavailable`；确无对应模型权限时仍返回
`403 / access_key_group_forbidden`。手动禁用整个模型规则保持禁止调用。

上述冷却仍是当前进程内状态，不新增数据库写入或后台定时任务，重启后不保留。
