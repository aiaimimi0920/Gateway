# 凭据池三级测试策略

## 目标与验收

自动和手动共用固定大小、内部滚动的弹窗及同一份选择状态。模式切换只改变
执行方式，不改变模型、测试集、临时提示词和账户选择。手动明确触发一轮；自动
由后台按已保存并生效的策略定时执行，关闭网页不会停止计划。

策略 owner 是路由 revision：池 `test_policy`，池内身份子池
`subpool_test_policies[credential_identity_category_id]`，账户 `test_policy`。
默认账户用池的 `default_account_test_policy`。账户覆盖优先于子池，子池优先于池；
未配置时继承，显式关闭自动仍是覆盖。保存父策略不复制或擦除账户策略。
子池是池内 Free/Plus 等单一身份分类，不改变顶层 `account_groups` 多组路由语义。

临时提示词加入当前表单测试集，切换模式保留。手动运行不持久化；明确保存策略
才进入路由草稿，沿现有配置自动保存流程提交，成功后生效；不新增额外保存按钮。
界面明确提示此提交边界与额度成本。修改间隔不清空已占用的到期槽。

## 运行合同

- 保留旧 `prompt/model/credentialIds` 手动 API；空 body 在存在新策略时执行有效保存策略，
  无新策略时保留旧联通探测。
- 新 `testPlan` 包含自动开关、1–10080 分钟间隔、全模型或精确多选模型、可勾选用例。
- 每用例可配置标准答案和难度 1–3；无标准答案只验证生成，不参与能力评分。
- 每次调用要求完整非空生成，不用 `/models` HTTP 200 代替可调用证据。
- 联通成功与答案正确分离。回答错误不惩罚 breaker、不标记凭据失效。
- 能力等级只是选定测试集的测评结果，不是通用智商或供应商模型排名；显示正确率、
  标准答案、实际回复和评级依据。没有有效评分证据时为“未评级”。
- 精确账户执行无池 fallback；池/子池手动一轮尊重更下层已保存覆盖。
- 自动与手动复用计划执行器；有界串行调用、单调用 60 秒、单轮 300 秒准入窗口、
  全轮最多 128 次调用、最多 128 个账户及每账户 128 个模型×用例组合。
  已开始的最后一次调用可完成其 60 秒超时；越界拒绝或明确标记未执行，不伪称失败。
  自动预算耗尽后不占用其他账户的调度槽，下个 tick 可继续到期账户；整轮固定路由
  revision，配置变更后不再准入旧轮次调用。
- 计划与最近一轮结果保留重启兼容：本地 SQLite 加法式初始化，服务器 Redis TTL。
  不修改现有数据版本和凭据；只新增测试 owner 的表和记录，旧数据原样保留。
- 评分先 trim、再忽略大小写精确匹配；正确率低于 80% 为低于标准，有调用未完成为
  证据不完整，无评分证据为未评级。其余按通过的最高难度显示 L1/L2/L3。
  逐项预览最多 320 字符；匹配使用执行器保留的完整、有界、秘密脱敏回复。

## 非目标

不新增 LLM 裁判服务，不自动消耗真实账户额度进行开发验证，不修改路由评分或
自动删除账户，不提交/推送未经用户要求的改动，不关闭正在运行的旧版。

## 实施顺序

1. 建立策略 DTO、边界验证与三级解析，保护旧文档读写。
2. 统一多模型×用例执行、独立评分、自动调度和最近结果持久化。
3. 接通池/子池/账户统一弹窗及显式草稿保存；稳定尺寸与选择状态。
4. 聚焦模拟上游、继承、评分、重启与 UI 回归，类型/编译/格式/行数检查。
5. 按正式构建脚本交付唯一 Windows 包，检查图标、完整性与隔离启动。
