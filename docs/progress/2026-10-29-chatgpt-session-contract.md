# ChatGPT Web 会话生命周期与导入拒绝处理

## 已证问题与修复范围

人工网页登录完成，不等于 Gateway 已取得可用的会话。保留原始 profile 的只读探测中，
`/api/auth/session` 返回 HTTP 403，并明确带有 `cf-mitigated: challenge`。这证明该请求
被浏览器验证拦截，不证明用户没有完成登录、账号已失效或指定模型没有权限。

本次不自动处理验证，也不重新控制该人工登录窗口。保留其 profile；不重启或修改现有
4200 Gateway，不修改在线凭据、数据库、代理或网络出口。

### 生成链的 metadata cache 与 HTTP session 不能混为一谈

`bootstrap_site` 原先在页面 metadata cache 命中时直接返回；新建的请求局部 Cookie
owner 因而不能接收本次首页正常设置的 Cookie。两个参考项目的普通文本链则每次先
初始化首页，再使用同一账户上下文请求后续阶段。

现在即使 metadata cache 可用，也先执行同源、禁止重定向且有界的首页初始化。缓存仅在
HTML metadata 解析不成功时作为后备，不再掩盖首页 HTTP 拒绝或验证响应。Cookie 仍然
属于单次账号请求链，不保存回在线凭据，也不跨账号共享。

显式缓存 requirements/sentinel 的既有快捷合同未改；不能据此宣称所有配置都必然请求首页。

### 目录保留已保存的账户上下文

目录请求的字段白名单现保留已有的 session ID、客户端版本、build 与语言字段及已支持的
别名，避免目录和生成无故使用不同的账户上下文。没有伪造这些字段，也没有增加任意请求头
或目标地址覆盖能力。目录仍固定使用所选凭据的 Bearer、固定官网端点和独立 Cookie owner。

### 会话读取明确拒绝时停止，而不是轮询成登录超时

浏览器会话读取现在区分明确的 `cf-mitigated: challenge` 和普通 HTTP 403。二者都立即
停止自动轮询，保留准确的固定错误码，仍按原合同清理程序自己拥有的临时会话。
页面尚未就绪、临时网络/CDP 读取失败仍可在原有预算内重试。

管理错误文案明确说明会话读取未完成，不把它等同为用户登录失败。不转发响应正文、
异常详情、Cookie、token，也不会通过替代提取来源或浏览器配置绕过验证。
