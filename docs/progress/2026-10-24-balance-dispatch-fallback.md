# 预扣费失败与手动禁用后的授权回退修复

## 发现与改动

- 用户提供的中文 403 预扣费消息原先落到普通鉴权分类；即使已识别的英文余额错误，
  现有 403 熔断反馈也会忽略。本轮统一识别明确的预扣费/余额准入拒绝。
- 新增具体凭证级余额熔断票据，与原来的分组/模型熔断分离。首次拒绝直接进入
  level 3（32 分钟），到期试放失败进入 level 4（60 分钟）。同凭证跨模型共用限制，
  同组健康凭证不受连带禁用；默认账户按服务商默认凭证身份隔离。
- 候选解析原先每个服务商只选择一个凭证。本轮最多保留 6 个不同合规凭证，主选
  只推进一次轮询，备选不增加首次服务商加权机会。请求总预算仍为原来的 6 次。
- `Access key has no permitted account in its entitlement groups` 是 Gateway 本地错误，
  原来在候选为空时一律产生，并不能证明禁用后的上游被调用。现在对已授权但全部
  停用或暂不可用返回 503；真正无模型授权仍保留 403。
- 绑定账号分组的访问密钥可在具体授权成员内使用支持同一模型的备用服务商；只在
  请求头选择分组不增加跨服务商授权。模型规则整体禁用、本地 key provider/model
  限制、凭证 enabled、协议及发送前复核仍然有效。
- 本地模型目录先取得内部模型清单，再实施完整授权与可用性过滤，避免首选服务商
  停用时提前隐藏仍有授权备用服务商的模型。未扩大 PostgreSQL bundle 授权。
- 输出前 SSE 的结构化余额错误保留原消息，不让附加的 code 前缀破坏识别。
  已输出或移交的流不重放。余额错误优先于泛化 key/token 文本诊断，避免 request-id
  恰好含 key 时误记成永久凭证失效。

## 验证

`C:/Users/Public/nas_home/AI/GameEditor/linshi/gateway-balance-dispatch-20261024`。

- 路由单元测试：222 通过，覆盖熔断期限、代际隔离、试放、2/3/6/8 账号轮询、
  多目标映射及请求分组不能擅自扩大回退权限。
- HTTP 发送测试：51 通过，使用真实 loopback HTTP/SSE 模拟上游；余额失败账号只
  被调用一次，缓存队列不能绕过冷却，同组健康凭证与已授权服务商可以接替。
- 访问密钥分组合同：4 通过，验证禁用首选的两个凭证后只调用授权备用凭证，
  组外账户零调用、无可用账户为 503、无模型权限为 403、禁用模型规则仍禁止调用。
- 有效行检查器：31 通过；ratchet、相关 rustfmt 与 scoped diff 检查通过。
  本轮修改的生产源码均不超过 500 有效行，无需增加例外或重建 baseline。

## 边界

源码与本地验证已完成；没有生成新的交付包、替换正在运行的 EXE、修改真实凭证/
数据库、提交或推送。未执行付费上游、正式发布审计、PostgreSQL 部署或用户原生界面
全面回归。编译仍存在既有 unused/dead-code 警告，本轮未扩展到无关清理。

余额熔断仍为单进程有界运行状态，重启不保留，不改变人工启停标志或存储格式。
运行中的旧包不会自动获得这些源码修复，需要后续使用新的 devtest 包验证。
