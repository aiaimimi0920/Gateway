# 服务商内部 ID 在线迁移：兼容层第一阶段

后续本地授权兼容与最新验证结果见
[第二阶段记录](2026-10-28-provider-id-authorization.md)。本文保留第一阶段检查点。

## 运行边界

当前 AI 调用依赖运行中的 4200 Gateway。禁止为此任务停止、drain、重启或
改写其数据。旧的离线 Python 迁移脚本不是在线执行入口。本阶段只修改源码，
在 `linshi` 下使用合成 SQLite 测试数据，不调用任何上游模型。

配置本来支持热发布，但热发布不等于整个身份体系支持在线改名。只有健康状态、
权限、路由、审计、价格和队列引用都完成兼容，才能接入实际迁移协调器。

## 本阶段代码

- `src/local_runtime/model_identity.rs`：SQLite 模型健康状态旧 provider ID 与
  canonical ID 映射，以及已有状态主键的兼容映射。只新增可选表，不提升
  `PRAGMA user_version`，没有启动时自动改名、HTTP 入口或配置保存触发器。
- 状态写入在同一个 `BEGIN IMMEDIATE` 内解析 ID、计算主键、校验 CAS 和写回。
  改名前选中旧 ID 的请求完成后不能重新生成旧身份记录。
- 恢复快照读取使用一个 SQLite 读事务；列表筛选和已有旧主键查询在同一条 SQL
  中解析映射。路由健康读取复用快照入口。失败 journal 在原有 gate 内解析身份。
- 改名仅移动身份和主键，保留 credential ID/ref、协议、模型、健康字段和时间。
  改名前的非空 payload checkpoint 失效；旧 undo 不强行解析 ID，避免恢复旧身份。
- 冲突拒绝合并；拒绝映射链、环及改向。相同映射重试幂等。
- 存储原语保守限制为整个健康表最多 256 行、映射最多 256 项。超限拒绝，不持有
  单个写事务扫描无限数据；这不是大规模后台迁移实现。

## 尚未满足的激活条件

1. 路由配置、重试和回退必须识别同一 provider 的别名，但不能产生第二套候选。
2. access key 的 provider 限制、模型发现及请求授权必须同义，不能扩大授权范围。
3. 默认账号和隐式 credential ID 必须显式固定。当前原语只迁移 provider ID，
   不解决 `old::default` 到 `new::default` 的账号身份变化。
4. 审计创建、路由、终结、历史查询和压力统计须一致；价格、refill 互斥和任务
   引用也必须使用同一身份。历史配置 revision 不改写。
5. 协调器须持有健康 publication/gate，协调配置发布与持久状态事务，提供可恢复
   journal、备份及明确的冲突恢复流程。当前没有生产可调用的迁移入口。
6. 映射只为改名时已存在的状态保存旧 hash；新生成状态应通过 provider 身份入口
   查询，不能把任意旧 hash 查询当成通用兼容 API。
7. 激活后的数据不能让不理解别名的旧 EXE 并发写入。可选空表兼容不代表激活后
   仍能无条件降级；部署与存储版本门禁需在协调器阶段完成。
8. 尚未进行真实 HTTP/流式/重试中的在线迁移验收，也未验证不停服务的新旧版本
   接替。不能把 SQLite 并发单元测试称为业务流式验收。
