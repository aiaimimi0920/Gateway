# 运维工作区信息架构与视觉优化

## 本轮范围

将三个可同时展开的大折叠区改为“运行概览 / 请求排查 / 异常处置”任务视图。
数据仍由 `useOperationsData` 统一持有；没有改变 API、请求过滤语义、路由、凭证或数据库。

- 概览直接显示运行指标、当前运行异常和当前查询中的近期失败请求。
- 请求筛选保留全部六个字段；状态、条数上限常驻，其余字段渐进展开。
  支持 Enter 提交；修改、重置、展开、切换视图均不会自行提交查询。
- 错误摘要直接显示在请求记录中；回退与错误分布按需展开。
- 保留事件确认/解决、单行 busy 与管理锁、自动处置、分析与导出记录。
- 保留 PostgreSQL 能力三态，不将 SQLite 不支持的能力伪装成空数据或读取失败。
- 没有新增运维工作区的手动刷新按钮。应用壳层已有的全局刷新入口未修改。
- 顶栏时间仅标注“概况采集于”，不承诺自动轮询，也不代表所有面板的采集时间。

视觉采用现有 Neuro 语义令牌：紧凑页签、连续指标条、细分隔表格、错误文字提示；
布局断点按工作区容器宽度判断，适配侧栏占宽。没有引入新依赖或全站主题改写。
