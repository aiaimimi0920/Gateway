# 2026-10-24：站点健康按网关系统分层

## 目标与实现

用户要求官方独立服务保留独立适配器，New API／sub2api／One API 的部署站复用项目级通用适配器，
不按站点域名或某个健康接口创建对外变种。

- 新增 `new-api`、`sub2api`、`one-api`、`compatible-gateway` 四个系统级配置值。
- `discovery/readers.rs` 持有有限内部读取器和固定请求路径；`discovery/gateways.rs` 负责协商。
- New API／One API 检查前五种兼容能力，sub2api 只检查 v2 分组矩阵；未知类型兼容网关检查全部六种。
- 官方适配器保持原来的固定地址、无认证、分类语义和 OpenAI Codex 特例。
- React 主选择框分“网关系统”和“官方服务”，不再罗列性能摘要、slot、embed 等内部接口。
  具体读取器保留在诊断中；默认摘要只说明是否确认健康来源。

“通用”表示共享能力解析，不代表每个部署必然开放模型监控。One API 的模型健康依赖扩展；
不能把存活结果当模型成功率。自动模式也不凭一个兼容接口宣称已确认网关软件身份。

## 兼容与认证

六个旧 adapter ID 继续原样读写，仍固定执行单一读取器。已有方案打开或修改其他元数据时
不会自动改成系统级协商；界面将其显示为对应系统，未知来源扩展显示为兼容网关，并保留旧读取器说明。
用户可以明确切换到网关级自动识别。转换改变 secret audience，因此旧密钥不能 `Keep`，
需要显式 `Replace`／`Clear` 和既有敏感字段授权。没有数据库版本升级或运行数据迁移。

系统级认证先做真正匿名的浅层能力识别，再只选择一个读取器发送监控凭据并完整检查分组。
认证失败不向其他读取器重试。无公开证据时，只有 New API 摘要及 sub2api 矩阵拥有标准认证目标；
One API／未知类型返回 `authentication_target_unconfirmed`，不猜扩展、不发送密钥。
公开识别证据不作为最终分组健康率发布。

原有 25 秒总超时、并发 2、固定 DNS、禁代理／重定向、响应体限制和详情预算保持有效。
新协议说明见 [网关适配器与内部读取器](../site-health-gateway-adapters.md)。
