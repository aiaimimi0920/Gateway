# SAP AI Core：Server Hosted 公共推理与 X.509

## 验收结果

- 在启用 PostgreSQL 与 Redis 的两个独立 Server AppState 中，实例 A 通过管理 API 新建 SAP Provider Account、X.509 Credential 和项目模型别名。两实例都使用空路由文件；实例 B 从 Hosted 数据读取配置，以合成 Gateway 公共 Key 调用，不依赖本地 YAML 或管理 Token 识别调用者。
- Chat、Messages、Responses 三个公共入口的 JSON／SSE 共 **6 次成功**，上游均走同一 Azure Chat 部署，逐次确认只发送一次。证书仅在独立的 mTLS OAuth 监听器参与握手；六次生成共一次成功 Token 交换。推理携带短期 Bearer、指定资源组和 `api-version`，不携带调用者的 Cookie、管理 Token、部署别名或 Service Key；Responses 与 Messages 是 Chat 桥接，不是上游原生端点。
- 实例 A 从 PostgreSQL 读回 **6 条完成审计**：每条均归属项目、公共调用身份、精确 Provider Account 与 Credential，模型解析正确，`route_attempt_count=1`，记录 2／3／5 tokens（合计 30 个）。检查了管理响应、公共响应和审计 trace 的凭据脱敏。该结果是公共请求用量归属，不是现金／预付扣费验收。
- 无效入站 Key 返回 401；模拟证书服务端主机名不匹配返回 502／`sap_aicore_token_failed`，两条负对照均未向推理端发送；数据库读回后者为 1 条失败审计，未记录生成用量。

只新增隔离回归及复用测试夹具，没有改生产路由、存储格式或鉴权策略。首轮测试的 HTTP 代理把 loopback 请求送到原监听器，导致逐次计数取错位置；修正为单个生成监听器并按请求生成唯一响应 ID 后，完整用例通过。隔离 PostgreSQL／Redis 已停止，测试数据保留；未访问真实 SAP、未消耗额度。双 AppState 不等同双后端 EXE，未生成新桌面包或执行原生点击。

验证：隔离 Hosted 用例 **1/1**；常规 SAP 回归 **37/37**（隔离用例默认忽略，已单独运行）；独立 `line-sap-aicore-chat` 的 lib／bins、定向 Rust 格式、有效行 checker **31/31**、ratchet、UTF-8 无 BOM 与 `git diff --check` 均通过。
