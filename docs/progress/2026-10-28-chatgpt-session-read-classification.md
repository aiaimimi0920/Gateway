# ChatGPT 登录后账号读取：错误分类与准备阶段修复

## 实际现象与证据边界

用户在 `gateway-devtest-20261028-190716-native-login` 完成网页登录后，没有看到
“已读取账号”。当前 4200 日志记录对应管理请求返回 HTTP 503，界面提示完成登录后重试。
这是 Gateway 管理请求状态，不代表 ChatGPT 会话接口本身返回了 HTTP 503。

已核对运行实例和源码：专用登录 worker 已退出，浏览器 profile 在最终清理时回收；
没有在两阶段交接之前删除或复制 profile。真实 Chrome 的空白 profile 探针也同时接受
普通 Windows 路径和 verbatim 路径，不能据此认定 `\\?\` 是登录失败根因。

已确认的代码缺陷是：任何页面执行异常、会话请求非成功状态、非 JSON 页面及 token
解析失败，都被压成 `login_required`。该信息不足以判断用户是否已登录。
CDP endpoint ready 也不代表页面文档和会话已经 ready。之前成功的独立实验在重开
浏览器后先初始化隔离网关，天然具有额外延迟；这只是时序差异，不是真账号根因证明。

## 最小变更

- 页面仍在加载或跳转时不提前请求会话；后续继续有界重试。
- 分开报告页面不可用、网络请求失败、HTTP 403/429/5xx、非 JSON、响应异常、
  token 格式不支持及已过期。只有缺少会话/token 等对应情况仍报告未登录。
- 页面仅返回固定白名单错误码；不传递异常原文、响应正文、Cookie、token 或邮箱到错误输出。
- 读取阶段预算由最多 25 秒扩大为最多 60 秒，仍受原有 205 秒总工作预算和
  220/225 秒 worker/父级期限约束，不扩大登录权限或进程所有权。
- HTTP 429 重试间隔至少 5 秒；完成或失败后仍由原 owner 回收自有进程和临时目录。
- 没有伪造“已读取账号”，也没有改动成功 UI 条件、凭据保存逻辑或当前 4200 实例。
