# DIM 原生 OAuth 本地实现进展

用户优先 OAuth／订阅账号接入，并明确两站暂时没有允许 Gateway 使用的 OAuth client 注册信息，
要求先完成本地实现。本记录不表示 DIM 已完整接入，也不表示真实注册、账号或订阅推理通过。

## 已落地的责任边界

- `src/protocol/dim_oauth/` 拥有两站独立 authority、显式 public client、discovery、
  PKCE/state/nonce、固定 loopback callback 验证、有界目录和 token/userinfo/JWKS 传输。
- 授权码只消费一次。存在 ID token 时必须验证 RS256、issuer、client、subject、nonce、
  时间和可选 access hash；userinfo subject 不同则拒绝，没有“验签失败退回 userinfo”。
  无 ID token 时明确标记 `UserInfoEndpoint`，不冒充 JOSE 认证。
- 凭据的 `dim_oauth` 保存 site/client/endpoint/subject/原 nonce/scope 等非 token 上下文。
  refresh 的 token 与可选 JWKS 验证共用一个 15 秒预算；省略 refresh token 保留原值，
  scope 只能缩小。按 [OIDC Core §12.2](https://openid.net/specs/openid-connect-core-1_0.html#RefreshTokenResponse)，
  refresh ID token 不要求 nonce，但存在时必须匹配初次授权。
- DIM 已接入原有 `token_refresh` 的 generation/attempt lock 和 durable grant owner，
  不另建平行刷新锁。reserve、result、apply、projection、replay、cache CAS 均携带 typed context；
  context 缺失时不改变旧凭据 JSON 和旧 material digest。
- 账号层不得继承或拼接 credential context；SecretPatch Keep 绑定完整站点/身份/目标，
  access/refresh token 仍走现有秘密字段与保存通道，不进入模型请求 payload。

所有材料均为合成测试数据，未读取真实 `.ng`、第三方客户端 profile 或 token。
没有内置参考插件的 client ID，没有 client secret，没有执行领取权益、签到、tunnel 或自动下载。
