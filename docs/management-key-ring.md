# 管理密钥列表

设置页的“管理安全”管理 Gateway 管理员密钥，与项目 API 访问密钥无关。所有有效管理密钥具有相同的管理员权限。

列表作用于当前 Gateway 实例的控制台和内部管理接口。独立 splitter 编排服务的控制令牌不属于此列表，仍由其部署配置管理。

## 行为

- 每行显示一个密钥，右侧提供显示/隐藏、删除和编辑，右上角“添加”创建行内草稿；最多 16 个有效密钥。
- 删除使用独立二级确认弹窗，默认聚焦取消；提交中不可重复确认或关闭。保存、删除成功后仅更新列表，不显示成功标签，失败保留错误反馈。
- 编辑支持改名和替换密钥，密钥留空只改名称；替换当前密钥后退出登录，旧值立即失效。
- 列表只返回 ID、名称、创建时间和是否为当前登录密钥，不返回密钥原文或密码哈希。
- 至少保留一个有效密钥。撤销当前密钥需要确认，并退出当前客户端；其他密钥继续有效。
- 服务端在原有持久化写锁内重新认证、读取、修改和原子写入，避免并发撤销最后两个密钥或丢失添加操作。
- 撤销清空认证缓存和秘密访问授权。认证缓存只保存内存中的指纹和匹配 ID，最多 64 条，每次仍检查磁盘上的列表版本。

## 兼容与接管

未添加或编辑密钥前，继续使用原来的环境变量/默认密钥或 `admin.json` v1 单密钥行为。
首次添加或编辑时，将当前有效密钥纳入 `admin.json` v2；添加保留“初始管理密钥”，编辑则按用户输入修改对应记录。
此后持久化密钥列表是认证依据，环境变量不再覆盖列表，也不会在重启后复活已撤销的密钥。行内添加时提示这一行为。
既有 v1 管理员记录会先备份到 `admin-before-keyring.json`；不备份环境变量明文，不改写凭据、路由或项目 API 密钥。
任何哈希写入失败都会阻止切换。新格式为空、损坏或版本不受支持时认证失败，不回退到默认密钥。

这是认证格式扩展，不应将旧版本程序指向已启用列表的数据目录。旧版本不能正确执行多密钥撤销语义，尤其不得通过旧程序的环境变量认证路径绕过撤销。
需要回退时，管理员必须先停止相关实例，明确选择恢复的密钥及其撤销影响，再从受控备份恢复；不要自动覆盖 v2 记录。
旧的单密钥轮换接口在 v2 下返回冲突，客户端应使用添加/撤销操作。

## API

`GET /v1/internal/gateway/console/management-keys` 返回 `{ keys: [...] }`。
同一路径 `POST` 接受 `{ action: "add", name, token }` 或 `{ action: "revoke", id }`。
编辑使用 `{ action: "edit", id, name, token? }`，省略 token 保留原密钥；显示使用 `{ action: "reveal", id }`，返回 `{ token: string | null }`。
请求使用既有管理认证头和控制台来源/远程访问约束；响应 `no-store`。新增密钥只在请求体内传输，不进入 URL、日志或浏览器持久化存储。

测试覆盖环境变量接管、v1 迁移、重启后撤销、不存明文、最后一个密钥保护、输入/认证边界、缓存/秘密授权失效，以及前端添加/确认撤销/当前会话退出。

## 按需显示与存储边界

新增或替换的密钥另存可选 `sealedToken` 字段，使用 AES-256-GCM 和每次随机 nonce 加密，附加认证数据绑定记录 ID 和认证哈希。认证仍只使用 Argon2 哈希，显示副本缺失或损坏不影响正常登录。该可选字段兼容既有 v2 记录，不批量重写旧数据。

本机随机加密主密钥保存在同一受管理状态目录的 `management-key-seal.json`。它不进入列表响应、发布包或浏览器存储；必须与整个状态目录一起按秘密文件保护和备份。加密不代替操作系统权限，也不能防御同时读取密文和主密钥的本机攻击者。主密钥缺失且已存在密文时不会自动生成替代主密钥。

眼睛按钮经过同样的管理员认证与控制台来源限制，响应 `no-store`，不依赖 URL 参数或 GET 缓存。当前登录密钥可从已验证的请求还原；其他旧哈希记录无法逆向恢复，返回 null 并提示通过编辑重新设置，不伪造明文。

前端仅在点击眼睛时请求明文，隐藏、切换会话、离开窗口或 60 秒超时后移除显示。测试覆盖编辑后的旧值失效、仅改名、旧记录兼容、错误认证、远程限制、密文损坏、主密钥缺失和敏感响应不落浏览器持久化存储。
