# 凭据池测试：计划列表、模型结果与自动/手动执行

## 操作

凭据池的“测试”入口先显示计划列表。左上角显示凭据池名称，“测试 / 结果”切换
列表与模型汇总，右上角“添加”进入配置表单。每行固定七列：名字、测试范围、
测试集、自动测试间隔、手动测试、编辑、删除；点击名字可展开最近结果。
添加/编辑保存后返回列表，配置沿现有自动保存流程提交。旧三级独立策略也显示在
列表中，可以编辑或删除覆盖；不会把继承状态虚构为一份已保存计划。

命名计划保存名称、稳定 ID、范围和完整策略。同一范围可以同时保存多个计划，
各自使用独立的调度槽与结果键。每池最多 32 个计划，每计划范围最多 128 账户；
一个全池，或同一类型的多个子池/账户。命名计划使用自己的完整策略，不受旧三级策略
覆盖。改名不改变 ID；不要复用已删除计划的 ID。手动运行命名计划前必须先保存，
等待配置生效，避免把未保存表单归属给已保存计划。

模型汇总基于各账户/计划最新保存轮次，而非历史累计。连通度是成功回复 / 实际调用，
调用错误率是失败调用 / 实际调用；不支持和未执行单列，不进入这些分母。答案错误率
仅统计成功调用中有标准答案的评分证据。智能度是测试集等级，不是通用 IQ。
读取及缓存最多 128 条结果 / 池，超出时明确提示；展开计划可独立读取其结果，
不会改变汇总采样集。页面自动刷新，不需要手动刷新；每轮读取完成后等待 5 秒，
编辑或手动执行期间暂停轮询。读取失败保留最近证据，并显示错误、自动重试。

计划编辑器仅配置和保存，不显示自动/手动页签、测试账户勾选区域或右侧结果。
配置表单为单列内部滚动区，底部操作区固定；窄屏计划表格使用局部横向滚动。
账户单点入口保持固定账户，直接进入配置表单，兼容保留底部“运行测试”；结果
不在编辑器内展示，应在计划列表展开或模型结果页查看。

1. 命名计划首行左侧为“计划”和短名称输入框，右侧选择“子池类 / 账户类”及下拉多选。
   子池类的“全选”保留原全池语义，包含未分类及以后新增的账户；取消部分子池则保存
   明确的子池集合。账户类的“全选”勾选当前所有账户，保存明确的账户集合，不自动
   纳入以后新增账户。空选择不能保存。多选面板使用覆盖层，不撑开表单；Escape 先关闭
   下拉并恢复按钮焦点。旧三级策略编辑器仍保留原范围控件；账户卡牌入口固定该账户。
2. 选择“全部配置模型”或勾选精确模型；未声明模型时可手动添加。
   全部模型在每个账户上使用它自己的 `supported_models`，为空时继承池配置，
   两者均为空时使用 `default_model`。映射别名不是凭空获得的可调用能力。
3. 勾选测试集的一部分或全部，可添加临时提示词、可选标准答案和难度 L1–L3。
4. 保存计划后在列表点击“手动测试”，执行保存范围内全部启用的账户，不再额外勾选
   测试账户。多个对象串行执行；关闭或授权失效后不再准入下一个对象。
5. 设置自动开关与间隔后，点“保存策略”；先更新路由草稿，再沿主界面现有的
   **配置自动保存流程**提交（编辑稳定后约 1.2 秒）。只有提交成功后才生效；若授权
   失效或保存失败，应处理界面错误，不能把“写入草稿”当作已生效。无额外“保存配置”
   按钮。后台只执行已生效的策略，关闭弹窗或浏览器不取消已保存的自动计划。

打开弹窗、进入编辑器或查看最近结果不会调用模型。只有手动执行或后台到期调度
会发送生成请求，可能消耗额度。关闭弹窗会终止客户端等待，不能撤回已发送的调用，
也不承诺客户端断开后的轮次一定完成持久化。自动开关关闭影响下一次准入，不能撤回
已经在途的调用。

## 继承与覆盖

优先级是 **账户独立策略 > 子池独立策略 > 凭据池策略**，覆盖的是完整策略而非
部分字段。未配置子级策略表示继承；子级显式关闭自动也是有效覆盖，不会被上级
自动开关再次启用。“继承”保存时删除该子级的独立字段；来回切换开关会
保留尚未保存的独立草稿，避免丢失临时编辑。

子池使用池内 `credential_identity_category_id`，如 Free/Plus；不会改变顶层
多归属 `account_groups` 路由分组。父级保存不复制或覆盖子级策略，也不改动凭据。
池/子池手动临时计划仍尊重更下层保存的独立策略；账户范围的临时计划仅测试该账户。
同时保存多个子池时只更新选中对象，全部对象校验成功后一次替换草稿；无效对象
不会产生部分草稿写入。全池、各子池与账户策略可同时存在。所选对象策略不同时
显示“配置不同”，需明确编辑统一策略或选择继承后才能保存，不静默覆盖。

配置位置：

| 对象 | 字段 |
| --- | --- |
| 凭据池 | `provider.test_policy` |
| 子池 | `provider.subpool_test_policies[categoryId]` |
| 显式账户 | `credential.test_policy` |
| 无显式凭据的池默认账户 | `provider.default_account_test_policy` |

## 结果与能力等级

“可联通调用”需要真实生成成功、回复非空且完整；不是 `/models` 返回 200。
调用失败、不支持或因预算/配置变更未执行会分开记录。错误答案仍可能可联通，
不会仅因答案不符合标准就使凭据失效或触发 breaker。

有标准答案的成功回复经 trim 和大小写归一化后精确匹配，显示正确率。低于 80%
显示“低于测试标准”；存在未完成调用显示“证据不完整”；没有成功评分证据显示
“未评级”；其余按通过用例的最高难度显示 L1 基础、L2 中阶或 L3 高阶。
这是**所选测试集的证据等级**，不是通用智能排名。复杂开放问题目前不使用 LLM
裁判；无标准答案的提示词只展示回复与调用情况。答案预览最多 320 字符，评分使用
保留的完整有界回复（上限 8192 字符），返回与持久化前沿用秘密脱敏。

最近结果按当前池/子池/账户过滤。后台读取仍要求管理认证与有效的精确 Secret Grant，
但首次登录后，客户端复用管理凭据自动取得和续期 Grant，测试或其他管理环节不再
要求重复输入密码。Grant 仅存内存；续期失败仍按原到期时间清理，失败后间隔
30 秒重试；切换身份、退出及卸载会使旧请求失效，不开放未认证管理 API。

## 运行与兼容边界

- 间隔 1–10080 分钟，后台每 60 秒检查到期账户；不保证精确到秒。
  变更间隔不重置已经占用的到期槽；下一次原定到期后，才按新间隔继续安排。
- 测试集最多 16 项，提示词最多 8192 UTF-8 字节、答案最多 4096 字节。
- 最多 128 个精确模型、每账户最多 128 个模型×用例组合；手动最多 128 个账户。
- 整轮串行，最多准入 128 次调用、300 秒；单调用最多 60 秒。
  已开始调用可完成其单调用超时。超预算不假装调用失败，自动不抢占剩余账户的间隔。
- 整轮固定路由 revision；检测到配置变化后停止新调用，无跨账户 fallback 或隐式重试。
- 当前生成矩阵支持 OpenAI-compatible chat 以及官方 Codex 账户；不支持的协议明确
  返回 unsupported，不用安全联通探测冒充答案测试。
- 本地 SQLite 使用加法式表初始化，不升级数据库版本或改写旧凭据；服务器 Redis
  使用命名空间绑定的原子到期槽与结果 TTL。最近结果和过期调度记录保留 30 天。
- 到期槽是防重复调度机制，不是跨自动/手动、跨实例的整轮互斥锁；多实例在长轮次
  跨过最短间隔时可能重叠。单实例后台串行；本功能不承诺账户永不并发。
- 同实例在预算耗尽后，从下一目标继续下一轮准入，避免短间隔大计划饿死后续计划。
  重启可改变首次轮次顺序，但不会清空或重置已占用的调度槽。
- 无新策略的旧配置保留 `scheduled_probe_*` 联通探测；明确保存新策略后才切换为
  生成式集合测试。旧单提示词 API 继续可用；空 body 有新策略时使用有效保存策略。

API：`POST /v1/internal/gateway/console/providers/{provider_id}/probe` 执行，
`POST .../probe/results` 只读最近结果，body 可含 `scope`；先过滤池/子池/账户，再限制
单次最多 128 个账户结果。浏览器用此只读 POST 保持与授权时相同的 Origin，不放宽
Secret Grant 的上下文校验。同 `/probe` 路径的 `GET` 保留兼容，但调用方须保持与
确认授权时一致的 Origin/Host 身份。新执行请求包含 `testPlan`、可选 `scope` 和 `credentialIds`；
响应在原账户结果中增加可选 `assessment`，旧字段和状态保留。

命名集合配置在 `provider.test_plans`：`[{ id, name, scopes, policy }]`。
执行请求 `{ planId, credentialIds? }` 从当前生效 revision 解析计划，不接受与临时
`testPlan`、`scope`、`prompt` 或 `model` 混用。只读请求可用 `{ planId }` 精确读取，
或 `{ includePlans: true, scope? }` 汇总当前池的旧结果和命名计划结果；响应可能包含
`truncated: true`。`assessment.planId` 只在命名计划结果中出现。旧三段存储键保持
不变，命名计划追加第四段，无数据库版本升级或凭据迁移。
