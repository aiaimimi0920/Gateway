# Cursor 账号凭据导入

## 范围

该入口只将本人授权的访问令牌导入 Gateway 现有凭据配置，核验身份并持久保存。
它不依赖本机 Cursor、CLI、SDK Bridge 或 Docker，不发送推理请求，不启用付费回落。
`auth_mode: cursor_remote` 与历史 `cursor_acp` 分开；新导入账号默认不参与调度。账号是否启用以列表的调度开关为准；通用后台探测不会发送推理请求。

### 正常启动的调用依赖

账号导入与启用账号后的远端推理均为 **100% 纯 Rust 进程内实现**（`src/protocol/cursor_auth.rs` 与 `src/protocol/cursor_remote/upstream/`），**不依赖本机 Node、Cursor 桌面端、CLI、SDK 或 Docker**，也不再读取 `GATEWAY_CURSOR_REMOTE_NODE`。
正常启动使用 Gateway 既有出站代理设置，不要求手填 Cursor 专用环境变量（`GATEWAY_CURSOR_REMOTE_PROXY_PORT` 仍保留为可选显式端口覆盖）。当前传输要求三个固定目标均经同一 IPv4 回环 HTTP CONNECT 代理建立验证证书的 Rustls `h2` 双向流；
代理关闭、bypass 或不兼容配置会明确报错，不直连或付费回落。历史废弃的 `cursor_acp` 运行时与配置入口已移除，未配置远端服务商时的保留名拒发契约不变。
这不改变导入默认禁用调用、后台探测关闭及原账号身份保护。
源码修正后的包与实际实例切换须分别验证，不能把依赖解析测试当作真实调用成功。

### 控制台「测试账号」与真实模型请求

通用探测不会向 Cursor 发送请求。修正后的「测试账号」对已保存的账号返回
`result.status=unsupported`，并区分已启用和已暂停；只有不存在的账号才返回
`404 console_credential_not_found`。服务商批测按所选账号列出「不支持」，不计通过或失败，
不更新模型健康。HTTP 200 仅表示控制台返回了测试说明，不表示 Cursor 回复了模型请求。
在仅选择 Cursor 的账号或服务商时，页面会直接说明此限制，不要求填写提示词或创建定时计划。

## 从管理界面导入

1. 在服务商目录选择 **Cursor 账号导入**，添加并保存服务商配置。
2. 在这个服务商下添加账号，**无需填写邮箱**；账号身份在网页授权后自动取得。
3. 点击 **生成 Cursor 授权链接**（旧手测包按钮名为 **授权并自动导入**）；
   如提示 Gateway 敏感操作权限，先完成权限确认，再点击。此步创建会话，不自动弹出浏览器。
4. 看到“授权链接已生成”后，点击下方 **打开授权页面**，在 Cursor 官方网页选择要导入的本人账号并批准当前挑战。
   此时原按钮禁用是为了避免重复创建，不表示点击未生效，也不表示浏览器未登录。
5. Gateway 自动接收令牌、调用 `GetMe` 比对完整 subject，读取并校验远端邮箱、保存凭据并读回。
   不需要回到聊天里确认，不需要另外点击“保存令牌”。
6. 只有同时显示 **材料已收到：是、令牌身份已核验：是、已保存：是** 才算这次导入成功。
   保存成功后列表自动刷新，面板保留成功提示。

更新已有账号时，应在该账号的编辑入口重新授权，保留原凭据 ID；禁止静默覆盖不同身份。
同一令牌再次通过核验时，若配置完全相同，直接确认原有修订，不制造失败或重复账号。
身份保护以已保存令牌的 subject 为依据，不把账号显示名称当作必须填写的邮箱。
“令牌身份已核验”仅表示远端身份与令牌一致；若它与原账号不同或重复导入，仍会拒绝保存，
显示 `cursor_import_identity_conflict` 并保留原凭据，不把材料有效误报为覆盖成功。
旧客户端仍可发送可选 `expectedEmail` 作为额外约束；省略或 `null` 表示自动识别，
显式空串／非法值仍拒绝，提供合法邮箱时必须匹配，不能改变同一 attempt 的绑定条件。

## 手动材料格式

勾选 **手动导入已有访问令牌**，同样无需填写邮箱，只在专用密码输入框粘贴访问令牌原文：

```text
<base64url-header>.<base64url-payload>.<base64url-signature>
```

这是三段 JWT 的结构示意，不是可用令牌。不要粘贴 `Bearer ` 前缀、Cookie、账号密码、
整个 JSON 或其他类型的 API Key。令牌必须尚有效且至少剩余 60 秒，并通过远端身份核验。
令牌只提交到 Gateway 管理 API；前端发送后清空输入框，不放入会话 Map、浏览器存储或 URL。
不要把真实令牌发到聊天、日志、截图或源码中。

## 中断与权限续期

- 关闭账号面板或一次请求断连，不会撤销后端已经接纳的导入；重开面板会查询同一 attempt，
  不自动再开挑战或重交令牌。此恢复记录仅在当前管理页面内存中，不承诺跨刷新恢复未完成挑战。
- 授权等待最多十分钟。Gateway 敏感操作权限比它更早到期时，已核验材料仍留在原任务内；
  点击 **确认权限并继续保存** 只续 Gateway 权限，不要求再次登录 Cursor。
- 取消只在提交之前有效；开始提交后不承诺撤销。会话到期、取消或任务结束会释放未保存材料。
- 配置修订发生冲突时不自动覆盖或重定基线。保留“已收到／已匹配”事实，先刷新配置再处理。
- 显示“保存结果未确认”时，先核对账号列表及事务恢复结果。已有账号使用原账号的重新授权入口；
  只有人工核对后才解除旧会话，不自动重放。
- 浏览器已登录、Gateway 收到材料、本人身份匹配、凭据已保存和推理可用是独立状态。
  不因状态查询失败或令牌过期就声称浏览器未登录。

## 存储与安全

复用 Gateway 现有 `SecretPatch`、修订 CAS 和 `commit_document` 持久化，不新增独立凭据文件，
不改变数据根选择规则。用同一个数据根重启后，已提交账号随活动配置恢复。
普通管理响应脱敏；通用配置入口不能跳过身份核验新增或替换此类令牌，也不能通过改账号类型
把已保存的 Cursor 令牌带入普通出站执行器。

**此处使用现有配置持久化，并不提供静态加密保证。** 数据根及备份包含敏感材料，按本机私密数据保护，
不要提交 Git 或随安装包发布；不要手工编辑数据库。
