# 出口网络波动保护与手动健康重置

## 出口网络波动

任一模型／凭据 circuit 因失败升级到时间禁用级别时，启动一次网关出口检查。
检查中的新业务调用先暂停；不把本地暂停当作供应商失败，也不继续遍历全池重试。
探针只由当前 Gateway 进程发送，与前端所在机器无关。

固定探针目标为 `https://www.gstatic.com/generate_204` 和
`https://cp.cloudflare.com/generate_204`，独立构建无业务凭证的 HTTP client，
沿用网关 HTTP client 的环境／系统代理策略。两个目标并发、每个最多 4 秒，
不跟随重定向、不读取正文、不附带 API Key、Cookie 或 Authorization。
任意目标返回 2xx 即视为出口可达；两者均失败则进入临时网络波动。
这是通用出口连通性信号，不等于所有供应商地址都可达。

- 首次探针可达：保留模型本身的真实失败／禁用等级，解除全局检查拦截。
- 首次探针不可达：设置 `temporary_network_fluctuation`，中文标签为“临时网络波动”。
- 波动期间：每 15 秒复查一次，暂停新业务和新手动／自动账号模型探测；
  已在途请求的失败仍进入原有反馈与审计流程。自动测试不消耗尚未认领账号的测试周期。
- 探针恢复可达：回退本次窗口内网络传输失败造成的 circuit 升级，以及相应的
  持久化模型健康处罚。既有等级和既有截止时间原样恢复，不全局清零、不延长旧截止时间。
- SQL 回退未确认：保留波动标记，下一轮重试，不先宣称已恢复。

当前状态通过既有站点健康管理响应中的 `gateway_network` 返回，包括 `status`、
`label`、`epoch`、受影响 circuit 数、窗口失败计数和上次回退数量。
检查／波动拦截使用 `gateway_network_unstable`，终止同次请求的供应商 fallback。
网关不会代替调用方自动重放已经失败的业务请求。

## 回退与并发边界

复用现有健康存储，不新增第二套数据库，不改变存储版本。
窗口和回退检查点仅存在于当前进程内存，不宣称跨重启或跨实例的全局网络状态。
每个窗口最多记录 8192 个健康行，circuit 继续遵守原有 8192 key 上限。

内存 circuit 使用 generation 和网络恢复 generation 隔离旧完成。持久化回退使用
Local 原始 JSON payload，或 PostgreSQL 的 `xmin:ctid` 做 CAS。
期间有其他 owner／实例更新健康行时，不覆盖其新状态；发现中间写入后，后续失败
重新以该新状态为基线。恢复前启动、恢复后才交付的网络失败不再追加处罚。

真实的认证拒绝、额度不足、限流和不支持的模型与出口波动分开处理，不因外网恢复
被自动解封。生成探针保留原有 expected-state CAS；波动中的网络失败保留审计，
返回 `failure_not_penalized`，不会绕过 CAS 写冷却。

## 服务商调度开关与手动重置

现有服务商卡片没有独立的 `provider.enabled` 字段，其开关汇总实际账号的
`credential.enabled`，由已鉴权 Console route-config commit 接口保存。

整个服务商从可调度变为全池暂停、从全池暂停恢复，或从部分账号暂停恢复为全池
启用时，清除此服务商的运行期健康处罚：

- circuit 等级、失败连击、时间禁用和旧试探租约；
- 各 credential／profile／model 的失败计数、冷却、错误和 blocked 健康状态；
- Server 模式下的旧账号／凭据 breaker 和失败计数；
- 此服务商的 SmartRouting 可用性降权与会话粘滞缓存；
- 网络回退窗口中此服务商的旧检查点，避免随后恢复时复活旧限制。

凭据、账号启用开关、归档策略、配额、预扣费、计费、运行锁、其他服务商的健康状态
均不被清空。旧在途请求的失败由重置时间及 circuit generation 拦截。
只修改名称等普通配置不重置；仅暂停一个账号且其余账号仍可调度时不清兄弟账号全池。
手动恢复并不保证无效或已耗尽的真实凭据能成功，后续真实拒绝仍按正常规则处理。

路由发布与健康存储不是跨库原子事务。若配置已保存而重置失败，接口明确返回
`provider_health_reset_failed`，不能将其视为重置成功；刷新后重新切换进行恢复。

## 验证范围

定向测试包含逻辑时钟 circuit、loopback HTTP 探针、隔离 SQLite、鉴权 Console
提交路径、旧请求迟到、其他供应商不受影响、原有健康恢复 CAS 合同。
真实外网断网、供应商调用、PostgreSQL／Redis live、桌面手测及 EXE 包装属于独立验证。
本轮实际执行结果见对应进度记录和 `linshi/gateway-network-recovery-20261025` 证据目录。
