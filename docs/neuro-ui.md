# Neuro 组件库接入

前端使用独立仓库 `NeuroDesign` 的 `@neuro/ui`，不在 Gateway 维护第二份标准组件源码。当前采用本地目录依赖，React / React DOM 仍由 Gateway 提供。

## 本地开发

设计系统位于 `C:\Users\Public\nas_home\NeuroDesign`。从 Gateway 的 `apps/desktop` 到包的相对路径是 `../../../../../../NeuroDesign/packages/react/neuro-ui`。新机器和 CI 必须同时检出设计系统，保持该相对目录关系，并先安装、构建库再安装应用依赖。

在设计系统根目录安装开发依赖后，首次接入或检出路径变化时，先在 Gateway 的 `apps/desktop` 执行：

```powershell
npx --yes npm@11 install --install-links --ignore-scripts --prefer-offline --no-audit --no-fund @neuro/ui@file:../../../../../../NeuroDesign/packages/react/neuro-ui
```

核对 manifest、lockfile 的根依赖与本地包 `resolved` 均为新路径，且外部包锁定版本未变化。`.npmrc` 保持 `install-links=true`；仅路径改变时元数据可能不变，不能只靠 `ui:sync` 更新安装地址。随后日常同步执行：

```powershell
npx --yes npm@11 run ui:sync
npm run typecheck
```

`ui:sync` 显式选择 `--package @neuro/ui`，仅构建该 React 主题库，不构建其他主题、预览或原生组件。同步比较全部产物，相同则不重装，变化时刷新本地包并检查单一 React 实例。普通 `npm install` / `npm update` 不保证刷新同版本的 `file:` 包。不要与同一应用的 npm 安装、测试或构建并发执行同步。分发后的应用不需要设计系统源码；库更新后仍须重新构建应用。
