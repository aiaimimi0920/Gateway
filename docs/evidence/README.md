# Gateway Provider Evidence Records

This directory stores durable, secret-free provider evidence generated by
`tools/run-gateway-line-evidence.ps1`.

The full matrix runner is a source repository only tool because it requires
`Cargo.toml`, `src/`, and deployment verification helpers; it is not copied
into the portable release. The package keeps the standalone
`scripts/invoke-gateway-live-provider-canary.ps1` canary for dry-run and
explicit opt-in live checks.

## File Contract

- File name: `gateway-line-evidence-<run-id>.json`
- Schema version: `gateway-line-evidence/v1`
- One file represents one runner invocation and contains one record per selected
  provider line.
- Records are inputs to `tools/generate-gateway-provider-inventory.py`; they are
  not provider credential files.
- Generated command output and provider response artifacts belong under
  `target/provider-evidence/`, not in this directory.

Each record identifies the provider line, offline or live mode, manifest
execution mode, verification category, endpoint family, credential source
label, status, evidence state, classified failure data, readiness diagnostics,
fallback evidence, safe live-target summary, and Gateway-relative artifact
paths. Live target request bodies are held only in a short-lived temporary file
while the delegated canary runs; they are never persisted in the evidence
record or durable artifact directory.

`live_passed` requires a Gateway response-header v1 proof bound to the selected
provider line and to the same non-empty request ID as the canary result, with a
2xx HTTP status. GET targets use the same proof contract and are delegated
without a request body.

## Security Rules

Evidence may contain labels such as `manifest:api_key` or
`vault:openrouter-primary`. It must never contain the referenced API key,
bearer token, cookie, JWT, password, refresh token, session material, browser
storage, or private key.

Do not hand-edit a generated record to add request authorization data. Keep live
target files outside the repository, and review canary body/header artifacts
before sharing them. The runner and inventory validator reject known secret
material in generated evidence, but operator review is still required before
publishing external artifacts.

## Generation

Representative offline metadata validation:

```powershell
tools/run-gateway-line-evidence.ps1 -SkipCargo
```

Full offline focused matrix:

```powershell
tools/run-gateway-line-evidence.ps1 -All -LibOnly
```

Live calls are never made by default. The opt-in procedure and target/readiness
contract are documented in `docs/provider-evidence.md`.

## Inventory Integration

The runner regenerates and validates `docs/provider-inventory.json`
with the current evidence file. To rebuild an inventory from a specific record:

```powershell
python tools/generate-gateway-provider-inventory.py `
  --evidence docs/evidence/gateway-line-evidence-<run-id>.json
python tools/validate-gateway-provider-evidence.py
```

Keep historical records only when their external context remains useful. A new
record supersedes an older state by timestamp; it does not erase the older
observation.
