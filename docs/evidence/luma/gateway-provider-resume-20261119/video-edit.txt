Video editing
Edit existing videos with Ray 3.2 — source.generation_id, source URLs and inline video, strength, auto-controls, per-signal conditioning controls, and single- or multi-keyframe guide frames.
Modify existing videos with natural-language prompts using
ray-3.2
. This guide covers every parameter for
type: "video_edit"
requests. For generating new videos from text or anchor images, see
Video generation
.
Info
A video edit re-renders a previous video generation under a new prompt. Output
settings like
resolution
and
duration
live under
video
; the conditioning
that controls how much the edit preserves the source lives under
video.edit
.
Tip
Keyframes are the secret to a great edit.
Ray 3.2’s video-to-video model
is at its strongest when you pin the look you want at specific moments and let
it carry that intent across the clip. The prompt sets overall direction;
keyframes
(
video.edit.keyframes
) steer it precisely — locking
composition, characters, and styling at the frames that matter. For anything
beyond a quick restyle, reach for
keyframes
first. The
Luma
Playground
is a useful reference UI
for seeing how keyframes shape an edit before you wire them into the API.

Referencing the source video
Section titled “Referencing the source video”
A
video_edit
request needs exactly one source video. Provide it three ways:
1. A prior Luma generation
— pass the completed generation’s top-level
id
as
source.generation_id
. It must be completed, belong to the same client, and have a video output:
{
"source"
: {
"generation_id"
:
"d290f1ee-6c54-4b01-90e6-d701748f0851"
}
}
2. A hosted video URL
— pass a publicly reachable URL as
source.url
, with a
video/*
source.media_type
such as
"video/mp4"
:
{
"source"
: {
"url"
:
"https://example.com/source.mp4"
,
"media_type"
:
"video/mp4"
}
}
3. Inline base64 video
— pass the encoded bytes as
source.data
, with a
video/*
source.media_type
:
{
"source"
: {
"data"
:
"AAAAIGZ0eXBtcDQy..."
,
"media_type"
:
"video/mp4"
}
}
4. An uploaded file
— a video uploaded via the
Files API
, referenced by its
file_id
(the MIME type is recorded at upload, so no
source.media_type
is needed):
{
"source"
: {
"file_id"
:
"a1b2c3d4-e5f6-7890-abcd-ef0123456789"
}
}
Note
source.url
and
source.data
both require a
video/*
source.media_type
(such as
"video/mp4"
) — the route uses the MIME prefix to choose the video
ingest path before fetching any bytes, so a missing or non-
video/*
value is
rejected. Source videos must be 18 seconds or shorter.
Tip
Use inline
source.data
only for small media files. For anything larger,
reference a prior
source.generation_id
or host the file and pass
source.url
instead of inlining.
image_ref
is rejected on
type: "video_edit"
; guide the edit through the prompt, optional
video.start_frame
, and
video.edit
.
Edit controls —
video.edit
Section titled “Edit controls — video.edit”
The
video.edit
object carries the video-to-video conditioning. It has three conditioning fields —
strength
,
auto_controls
, and
controls
— plus two multi-keyframe anchoring fields,
keyframes
and
keyframe_indexes
(see
Keyframes — the control surface for edits
below).
auto_controls
Section titled “auto_controls”
Boolean. When
true
, the model derives the full conditioning schedule from the source video — the recommended default. When omitted, supplying
strength
or
controls
implies manual mode.
Tip
Start with
auto_controls: true
. Reach for
strength
or
controls
only when
you need finer control than auto mode gives you.
controls
cannot be combined
with
auto_controls: true
.
strength
Section titled “strength”
A preservation-vs-reimagination preset (
VideoEditStrength
). Nine values across three bands; lower numbers within each band are lighter, higher numbers stronger. Supplying
strength
implies manual mode unless
auto_controls
is explicitly set.

Keyframes — the control surface for edits
Section titled “Keyframes — the control surface for edits”
Prompt and
video.edit
controls set the overall character of an edit;
keyframes are how you direct it precisely.
This is where Ray 3.2 edits go from “restyled” to exactly what you intended: pin a guide image at a chosen source frame, and the model honors that look at that moment, then interpolates the frames in between. The more intent you pin — the opening beat, a mid-clip moment, the final frame — the more faithfully the edit tracks your vision. For most non-trivial edits, keyframes are the single biggest lever on output quality.
You can anchor an edit two mutually exclusive ways: a multi-keyframe set (recommended), or a single guide frame.
Tip
Keyframing is a complex feature. The
Luma
Playground
is a helpful reference UI
for exploring how guide frames and their positions affect an edit.
Multiple keyframes —
video.edit.keyframes
(recommended)
Section titled “Multiple keyframes — video.edit.keyframes (recommended)”
Pin guide-frame images at arbitrary positions in the source video’s frame grid using two parallel arrays under
video.edit
:
keyframes
— a list of guide-frame images (up to 64), each taking the same
ImageRef
shape as
source
/
image_ref[]
(a
url
, inline
data
, a
generation_id
, or a
file_id
).
keyframe_indexes
— a parallel list of non-negative, unique frame positions in the source video’s frame grid where each
keyframes[i]
is anchored.
The two arrays must be the same length, and you provide both or neither — one without the other is a
400
. The example below pins three beats across the clip — opening, middle, and close — so the edit holds the look you set at each:

Single guide frame —
video.start_frame
Section titled “Single guide frame — video.start_frame”
For a quick edit anchored only at the first frame,
video.start_frame
takes a single guide frame (an
ImageRef
). It’s the one-anchor shorthand:
start_frame: X
is equivalent to
keyframes: [X], keyframe_indexes: [0]
, so the two are mutually exclusive — setting both on the same request is a
400
.
end_frame
is generation-only and rejected on edits. Reach for the multi-keyframe form above whenever you want control past the opening frame.
HDR on edits
Section titled “HDR on edits”
video.hdr

Note

(not

Aspect ratio on edits
Section titled “Aspect ratio on edits”
The output preserves the source video’s aspect ratio. Setting
aspect_ratio
on a
video_edit
request is silently ignored — same behaviour as on image edits.
