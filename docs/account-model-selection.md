# 账号模型双栏编辑

账号表单仅显示品牌名与账号 ID，不再提供账号名称和账号覆盖地址输入。
已有账号的 `account_name`、`base_url` 仍被读取并原样保留；不迁移、清空或改写已有凭据。

“支持模型”包含可编辑的“拉取模型”和“手动模型”两栏，支持换行或逗号分隔。
“拉取模型”按钮只执行已接入的只读目录读取，目前包括 ChatGPT、NVIDIA、OpenRouter、Poe、Groq 和 Cohere。
ChatGPT 网页账号在保存后可通过按钮读取网页目录，与 Codex 的官方目录端点严格分离。
网页登录导入会在本次专用浏览器回收前尝试读取目录，成功时按 `models[].slug` 回填左栏；
读取失败仍保留成功取得的账号材料，显示独立目录错误，不把 403、非 JSON 或空目录当作登录失败。
目录不可用时可在右栏指定精确模型 ID，正常保存会登记路由；这是操作员声明，不等于已验证可调用，
也不会绕过账号本身的模型权限、上游验证或额度限制。不维护一份伪装为实时目录的固定模型列表。
未接入只读目录的服务商禁用该按钮，仍允许手动维护两栏；不会用生成式协议探测冒充目录读取。
已有“刷新协议”仍是显式协议探测，不会由双栏保存自动触发。
目录发现提示固定显示在“拉取模型”按钮下方的预留状态区，不再在表单底部插入新行；拉取前后保持弹窗、密钥栏与底部按钮位置稳定。

## 可选存储字段

```json
{
  "model_selection": {
    "fetched": ["directory-model"],
    "manual": ["custom-model", "directory-model"]
  },
  "supported_models": ["custom-model", "directory-model"]
}
```

- 两栏独立保存，`supported_models` 是去重并集。每栏最多 2048 个精确模型 ID，
  单个 ID 最多 256 UTF-8 字节，不允许空值、控制字符、首尾空白或通配符。
- 拉取成功仅替换左栏，保留右栏；失败不清空上次成功结果，允许手动模型保存。
- 同名模型出现在右栏时，后续目录移除该模型也不会丢失手动声明。
- `model_catalog` 和 `discovery` 保留原始目录/探测证据，不随编辑左栏伪造。
  手动模型或目录发现均不新增 `verified_models`、成功记录或账号权限。
- 保存同步账号模型池、服务商模型池和精确路由，保留其他账号、别名、路由优先级及禁用策略。
  Rust 编译以显式双栏并集为准，不重新加入被用户从左栏删除的原始目录项。
- 显式两栏皆空表示该账号不提供模型，不能走旧版“空列表继承”或模型兼容回退。
- 无此字段的旧文档保持原有读取和路由语义；编辑时按已存证据拆分旧列表。
  没有来源证据的旧模型归入手动栏，不声称恢复了未知历史来源。
- 旧账号原先继承的模型会先展开到编辑栏，避免仅打开并保存就意外禁用模型；
  新增非目录型服务商账号时，模板的既有模型填入手动栏，不冒充实时拉取结果。
- 不更改存储版本，不自动改写运行实例。关闭弹窗、切换服务商或撤销敏感权限会隔离过期目录结果。

## 定向回归

前端重点覆盖双栏交互、目录失败、取消/权限撤销、来源重载、手动同名保留及路由策略。
后端 `routing::config::tests::model_selection` 覆盖重载、候选选择、显式空列表、
旧格式兼容、模型别名、多目标映射和后台目录合并。
均使用本地 fixture，不遍历真实目录调用模型。
